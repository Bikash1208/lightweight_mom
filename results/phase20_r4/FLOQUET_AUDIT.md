# Phase 20 R4 — Floquet-cutoff audit

Finding (`FLOQUET_CONVERGENCE.md`): the solver's rank minimum (`2F + 1 >= n`) leaves isolated numerical lines in oblique-incidence results; the converged cutoff is `F = 2n`.
Phase 20 R1–R3 used the minimum (`n/2 + 1` or so). This audit regenerates and re-checks what depended on it. MODEL_ONLY throughout; no HFSS result exists for any of it.

## 4. Phase 26 (branch `phase26-leaky-tensor-cp`)
Phase 26 uses `MeshSettings(m, m, m)` / `(n m, m, max(n m, m))` with explicit per-direction orders `(n m, m)` for the supercell row, i.e. **F = n (1x), not the minimum** (R1–R3 used about n/2). Sensitivity test, mesh 24, F = n vs F = 2n
(`scratchpad` script, same cells as the tables; D 6.0 mm circle, slot 3.5 x 0.8 mm):
* single cells (no slot, slot at 0, 45, 90 deg): beta/k0 changes by 1.2e-4, 1.2e-4, 1.4e-4, 1.4e-4;
* 4-cell slot-angle supercell row: beta/k0 1.04513 -> 1.04500 (1.4e-4 k0), alpha/k0 4.78e-4 -> 4.74e-4 (0.8 %).
The Phase 26 gates are 0.01 k0 (beta) and a few percent (alpha): the effect is two orders of magnitude below them, and no isolated-line artefact appeared at these (kt > k0, evanescent) points. This is a **sample**, not a recomputation of every Phase 26 table point;
the other normal-incidence/Bloch scripts use the same F = n convention. The HFSS-validated single-hex result is not affected at this level. The app's unit-cell and hologram routers also use F = n (not the minimum).
